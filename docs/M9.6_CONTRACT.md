# Контракт M9.6 — режимы браузера: headed + CDP-attach

> 🌐 **Русский** (основная версия) · [English](M9.6_CONTRACT.en.md)

> **Статус**: Delivered (offline) · **Дата**: 2026-06-28 · **Волна D** (post-Foundation)
> **Покрывает**: M9.6 (GAP-M9-07, §F2/F3) · опирается на M9 design freeze (ADR-024) · вводит ADR-036 (Chromium-only) + ADR-037 (режимы запуска)

---

## Область

pw-executor получает два режима запуска браузера из эволюции §F (own-headless → headed → CDP-attach → co-pilot):

- **F2 — headed (видимый):** `chromium.launch({ headless: false })` — пользователь видит прогон.
- **F3 — CDP-attach:** `chromium.connectOverCDP(endpoint)` — Sentinel драйвит **существующий** Chrome пользователя (запущенный с `--remote-debugging-port`), переиспользуя его сессию.

**Вне области:** F4 co-pilot takeover/return — отдельная веха **M9.8** (после чат-UI). Новых RPC-инструментов нет — режимы переключаются env (как `PW_NO_TRACE` / `PW_IGNORE_HTTPS_ERRORS`). Движок — **только Chromium** (ADR-036).

## Контракт (что реализовано)

> ⚠ **ПОПРАВКА ADR-128 (2026-08-18).** Ниже — запись о приёмке вехи M9.6, и она остаётся записью о том, что было принято ТОГДА. Одно утверждение с тех пор изменено намеренно: в режиме CDP-attach усыновляется только **контекст** (сессия, cookies, вход), а страницу прогон **открывает свою** (`context.newPage()`) и закрывает её за собой на любом пути выхода. Браузер пользователя по-прежнему не закрывается, его вкладки не читаются и не управляются. Причина: два одновременных прогона вели одну вкладку и заявляли один `targetId`, поэтому живой вид отказывал обоим. Действующее описание — `ARCHITECTURE.md`, строка ADR-128.

### Резолвер режима (`pw-executor/src/launch.ts`)
- Чистая функция `resolveLaunchPlan(env) → { kind:'launch'|'cdp', headless, cdpEndpoint? }`.
- **Приоритет:** `PW_CDP_ENDPOINT` (CDP-attach) > headed (`PW_HEADLESS=0` или `PW_HEADED=1`) > headless (дефолт). Пустой/прочий `PW_HEADLESS` → headless (fail-safe к детерминированному режиму).
- Юнит-тест `launch.test.ts` (`node --test`, **без браузера**) — 5 кейсов покрывают приоритет и fallback.

### `ensureBrowser` (`server.ts`)
- **launch-ветка** (headless/headed): `chromium.launch({ headless })` + наш `newContext` с фикс. viewport 1280×720 / DSR=1 (детерминизм, GAP-RISK-009) + `storageState`/`ignoreHTTPSErrors` как раньше.
- **cdp-ветка:** `chromium.connectOverCDP(endpoint)`; контекст — **существующий** пользователя (`browser.contexts()[0]`, иначе `newContext`); наши viewport/DSR/`storageState` **не применяются** (это сессия пользователя); `STORAGE_STATE` игнорируется (логируется). ⚠ **Изменено ADR-128:** страница — своя (`context.newPage()`), вкладка пользователя не усыновляется.
- **Общее для обеих веток:** traceparent-route (если задан OTLP, M9.5), tracing (если не `PW_NO_TRACE`), adopt страниц — активная = первая существующая (CDP: открытая вкладка пользователя; launch: свежая), `pages[]` отслеживает все (M9.4 A6 без изменений). ⚠ **Изменено ADR-128:** активная страница всегда СВОЯ, а `pages[]` держит только её и попапы, поднятые ею; вкладки пользователя в него не попадают. **В CDP-режиме** эти env-gated побочки (route-инъекция заголовка + tracing) применяются к **живой сессии пользователя** — выставь `PW_NO_TRACE=1`, чтобы не писать её в `trace.zip`.
- **Teardown-гард:** флаг `attachedOverCDP` — в CDP-режиме мы **не закрываем** браузер пользователя (ни в cleanup `server.ts`, ни в SIGTERM-хендлере): просто выходим, CDP-соединение рвётся, Chrome остаётся жив.

### Детерминизм (ADR-037)
- **Голден-replay детерминирован только в headless Chromium.** Headed и CDP-attach — режимы **наблюдения / живого вождения**: иной путь рендера + (CDP) viewport/контекст пользователя → байты скриншотов **не** стабильны. By-design (см. `docs/DETERMINISM.md`).

### Движок (ADR-036)
- **Chromium-only by design.** `connectOverCDP` — только Chromium; голден-хэши различаются per-engine. Firefox/WebKit — отдельная decision-first веха (**GAP-OPS-001**), отложено.

## Отложено (live-verify, по «go»)
- **Headed:** `PW_HEADLESS=0` → видимое окно Chromium во время прогона (нужен display/X11).
- **CDP-attach:** запустить Chrome `--remote-debugging-port=9222`, выставить `PW_CDP_ENDPOINT=http://localhost:9222` → Sentinel ведёт **существующую** сессию пользователя; после прогона браузер пользователя **остаётся открыт** (проверка teardown-гарда).
- Brain-side: план/сценарий, явно выбирающий режим (напр. headed для демо) — отдельный шаг по необходимости; здесь доставлены примитивы pw-executor.
