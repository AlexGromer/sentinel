## Scope

An MV3 Chromium extension that adds **two new capabilities** on top of the already-built pw-executor:

- **Record (live capture):** the user clicks/types → a content-script captures events → grounded into scenario steps (reuses `reconcile`/`ground_scenario`, M9.2b).
- **Co-pilot takeover/return (§F4):** the agent drives the run ↔ hands control to the human ↔ takes it back — over ONE live session (on top of M9.6 CDP-attach).

**This is a design contract.** No code is written in this wave: it needs the live channel (M9.3 tail, GAP-M9-03) + a recorder + transport + a takeover protocol, none of which exist yet. Implementation is a separate wave after the prerequisites.

## Architecture (MV3)

```
┌─────────── User's browser ─────────────────┐         ┌──────── Sentinel ─────────┐
│ content-script  (recorder: click/input)     │         │                           │
│ service-worker  (MV3 background) ──WS/NM──▶  │◀───────▶│ control-API (M9.3, Go)    │
│ DevTools panel  (start/stop · takeover)      │         │   + streaming endpoint     │
│ chrome.debugger (takeover = CDP)             │         │ brain (reconcile→steps)   │
└──────────────────────────────────────────────┘         └───────────────────────────┘
```

- **service-worker** — MV3 background: holds the connection to the control-API, routes events.
- **content-script** — recorder: listens to `click`/`input`/`change`/`submit`, builds `{selector candidates, value (redacted), url}`.
- **DevTools panel** (optional) — UI: start/stop recording, takeover/return button, status.
- **chrome.debugger** — for takeover: attaching to a tab = CDP control (the same model as M9.6 CDP-attach).

## Contract (design)

### 1. Transport extension↔brain (ADR-038 → implemented in ADR-043)
- **IMPLEMENTED (M9.8-prep, ADR-043):** the control-API gained a **hand-rolled WebSocket** `GET /v1/stream` (client→server) — closing the remaining half of GAP-M9-14 (server→client SSE already existed, ADR-040). **No new dependency:** `net/http` `Hijacker` + a hand-rolled RFC6455 (handshake `Sec-WebSocket-Accept` = `base64(sha1(key+GUID))` + frame codec). Reuses the `127.0.0.1`-bind + bearer + Origin allowlist (ADR-032).
  - **Auth:** a browser `WebSocket`/MV3-SW can't send `Authorization` → the token rides in `Sec-WebSocket-Protocol` as `bearer.<token>` (constant-time). The client offers TWO subprotocols — `sentinel.recorder.v1` + `bearer.<token>` — the server validates the token and echoes back **only** the non-secret name `sentinel.recorder.v1` (the token never appears in the response header). CSWSH defense: Origin allowlist when configured (without it / without an `Origin` header the bearer token is the sole gate — acceptable under localhost-bind). The extension stores the token in `chrome.storage` (not in the repo).
  - **Ingest:** each text frame = one recorder event (NDJSON) → `runs/record-<session>/events.ndjson` (0700/0600); the server sends a greeting frame with the `session` id + an ack per event; `ping`→`pong`; 5-min idle timeout; cap 10000 events, 1 MiB/frame. Fragmentation is NOT reassembled (one event = one FIN frame; a fragment → close 1003). This is **transport + ingest**; record→scenario grounding is a separate wave (MV3-impl).
- **Alternative (air-gapped / no network port):** a **native-messaging host** (stdio) — Chrome ↔ a local binary over stdin/stdout; no port, but needs a per-OS host manifest. (NOT implemented; the alternative for air-gapped deployments.)
- Tracked: **GAP-M9-14 — client→server WS DONE.**

### 2. Action recorder (ADR-038, GAP-M9-13)
- content-script → events → service-worker → transport → brain.
- **Redaction:** values of `input[type=password]` and secret fields are **NOT recorded** (the same principle as `PW_NO_TRACE` / `secretRef` in pw-executor).
- Minimal `host_permissions` (`activeTab` / on request); recording **only on an explicit start**.

### 3. Record→scenario (reusing M9.2b)
- Event stream → `brain/scenario.py` `ground_scenario` / `reconcile` → steps **bound to real elements** (like describe-mode, but the input is recorded events instead of NL). No fabricated selectors.
- Output — `scenario.json` (the same format as M9.2b), ready to replay.

### 4. Co-pilot takeover/return (ADR-039, GAP-M9-15)
- **States:** `agent-driving` ↔ `human-driving`. A takeover signal (panel button) → the agent pauses, the human drives; return → the agent captures the state delta and continues.
- Built **on M9.6 CDP-attach** (the agent and the extension drive the same session over CDP).
- **Visibility:** Chrome shows the debugger banner on attach; auto-detach on return.
- Protocol: `takeover` / `return` / `state-sync` signals over the same transport.

#### 4a. Brain-side R3 — transport of the takeover signal to the in-flight brain (fork, 2026-06-30)
The brain runs as a **per-run subprocess**; takeover arrives **asynchronously** from the UI → the signal must reach the brain so it can do a LangGraph `interrupt`+persist (on the R2a checkpointer) and `resume` on return. Three options considered:
- **(A) Orchestrator RunControl gRPC (M8) — ✅ CHOSEN (user, 2026-06-30).** Extend the EXISTING brain↔orchestrator channel (`cmd/orchestrator`, RunControl — already does token-reconcile + abort + SIGTERM): `Control += takeover` (brain-facing, like `abort`; the brain ALREADY reads `Control` in the reply to every `ReportEvent`) + external RPCs `Takeover`/`Return` (like `Abort`). control-API/WS forwards the signal → orchestrator (sets takeover for `run_id`) → the brain learns it on the next `ReportEvent` → `interrupt`. **Pros:** purpose-built channel, push semantics, the brain already polls `Control` per step (zero new polling loop). **Cons:** touches `proto/runcontrol.proto` + orchestrator + brain + control-API; needs a running orchestrator (`ORCH_ADDR`).
- **(B) Polled flag via a shared store** — control-API writes a takeover flag to a shared store, the brain polls at superstep boundaries. Pro: no proto/orchestrator changes, reuses the R2a checkpointer. Con: a new polling loop, latency = the interval. **Rejected:** RunControl already gives a per-step pull for free (B would add a parallel channel).
- **(C) A new control-API→brain duplex (WS/socket)** — the brain holds a live connection to control-API. Con: a new channel + the brain gains a network client. **Rejected:** duplicates the orchestrator channel's role.
- **Risk-spike (2026-06-30, ✅ PASS):** LangGraph `interrupt()` mid-graph + `Command(resume=)` through `SqliteSaver` — pauses, persists the partial state, resumes from the SAME point, **including across a fresh process** (the takeover window may outlive the brain process). Foundation = the R2a checkpointer.
- **Pairing:** brain-side (interrupt/resume + RunControl `takeover`/`return` + WS forward) = my **R3**, tested via a fake client; extension/CDP/panel = @0xCoDSnet **#47**. As-built → **ADR-054** at implementation.

#### 4b. Brain-side R3 — IMPLEMENTED (ADR-054, 2026-06-30)

Variant (A), implemented **additively** (build not broken; behaviour without an orchestrator is byte-identical — `poll()`→`continue` ⇒ the nodes no-op, `plan_hash` unchanged):

- **proto (`proto/runcontrol.proto`):** `Control += bool takeover = 3` (distinct from `abort`; **abort > takeover** — a hard stop beats a pause) + external RPCs `Takeover(run_id, reason)` / `Return(run_id)` (modelled on `Abort`). Go+Python stubs regenerated with the same toolchain (libprotoc 33.5 / protoc-gen-go v1.36.11 / -go-grpc 1.6.2 → additive diff, no reformat).
- **orchestrator (`cmd/orchestrator`):** per-run `takeover` flag; `ReportEvent` replies `Control{takeover:true}` while pending (abort takes precedence in the same check); the `Takeover`/`Return` RPCs set/clear the flag under `mu`. The SIGTERM watchdog (on a budget breach) is untouched — a pause is not a breach, and no tokens accrue while paused.
- **brain RunControl client (`brain/runcontrol.py`):** `report()`/`poll()` return a **verb** `continue|abort|takeover` (was a bool). `poll()` is a 0-token heartbeat (`ReportEvent` with 0 tokens → budget +0) that surfaces a pending takeover without spending budget.
- **brain graph (`brain/graph.py`):** at the superstep boundary the `checkpoint` node polls the orchestrator; on a takeover it **arms** a state latch (`_takeover_armed`). A dedicated `takeover` node then does an **UNCONDITIONAL** `interrupt()` (LangGraph persists the partial state, `app.invoke` returns `__interrupt__`; the human drives the live browser via CDP). The decision is latched into STATE in the prior superstep so the interrupting node's `interrupt()` is reached identically on the resume re-run (a volatile poll guard would drop the return record). Return: the orchestrator's `Return` clears the flag → the brain resumes the **same thread** with `Command(resume=payload)` from the pause point → `takeover` → back to `checkpoint` (re-poll; handles a not-yet-propagated Return). Pattern from the risk spike (§4a).
- **abort > takeover in the wait window:** if the orchestrator ABORTS (budget breach / external Abort) while a run is paused for a takeover, the `checkpoint` node **converges** the run on resume (no extra perceive→act browser cycle) — a hard stop beats a return. Applies in both `_run_explore` and the cold-turn `_run_chat`.
- **brain driver (`brain/__main__.py`):** `_resume_through_takeovers` — if a run paused (`__interrupt__`), it waits for Return (poll → continue) and resumes with `Command(resume)` until the graph completes / `SENTINEL_TAKEOVER_TIMEOUT` elapses (default 1800s; `0` = wait indefinitely). It wraps the invoke in **both** browser paths (`_run_explore` + cold-turn `_run_chat`) so a takeover doesn't tear down the browser before Return. A no-op on the common path and without an orchestrator.
- **control-API/WS (`cmd/control-api/ws.go` + `main.go`):** the SAME `/v1/stream` socket accepts control frames in a **dedicated envelope** `{"type":"control","action":"takeover|return","run_id":"<id>"}` → forwarded to the orchestrator (`CONTROL_API_ORCH_ADDR`, gRPC `Takeover`/`Return`) → ack `control-ok`/`control-error`. Every other frame is a recorder event (events.ndjson, as before). The `type:"control"` namespace (NOT the bare verbs `takeover`/`return`) rules out a collision with a recorder DOM event that could legitimately use `type:"return"` (Enter key) and would otherwise be silently swallowed. `run_id` is format-guarded (`validRunID`: charset + ≤64); an unknown `action` / invalid `run_id` → `control-error`, never forwarded; fail-closed without an orchestrator; control frames have their own per-session cap. **Cross-run authorization** (binding `run_id`↔session) is deferred to M9-LIVE (THREAT_MODEL ❾).
- **Tests (offline, fake client):** `tests/test_r3_takeover_offline.py` (interrupt→resume · fresh SqliteSaver process · verb precedence · drive loop · no-orch regression · abort-during-takeover · cold-chat-takeover — 7) · `cmd/orchestrator/main_test.go` (Takeover/Return/precedence/isolation) · `cmd/control-api/ws_test.go` (parse/forward/missing-run_id/recorder-verb-collision; fake orchestrator on a unix socket). Gates: go build/vet/**race**/gofmt · pytest (13 files) · bilingual · gitleaks.
- **Gated to M9-LIVE:** live takeover (extension + `chrome.debugger`/CDP + panel = @0xCoDSnet **#47**) + per-run orchestrator socket discovery in the control-API. This wave is the transport + mechanics + an offline proof; the live-session e2e is the next wave.
