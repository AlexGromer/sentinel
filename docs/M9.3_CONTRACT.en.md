## Scope

ADR-023: driving Sentinel is available via **two paths** — MCP (brain-as-MCP-server, M7) **AND** a thin
**non-MCP HTTP control-API**. M9.3 adds the second path + makes setup-WebUI "live" (phase-2) + ships CI
templates. The chat front (OSS UI) is a separate sub-step on top of the control-API.

## control-API (phase-1 — ✅ DELIVERED)

> `cmd/control-api` (Go stdlib) implemented. Gates: `go build`/`vet`/`test` (5 httptest) + live `curl` smoke (healthz / POST-403 / bad-target-400 / CORS-preflight-204) — green. Docker `control-api` profile (port `127.0.0.1:8090`). ADR-032 in ARCHITECTURE §3.


A thin **Go HTTP service** (`cmd/control-api`, stdlib `net/http`, like the M8 report-service — no new
deps). This is the "non-MCP" path; the MCP path (M7) coexists (ADR-023).

**Endpoints (v1):**
| Method | Path | Purpose |
|---|---|---|
| GET | `/healthz` | liveness (no auth) → `{status:"ok", version}` |
| GET | `/readyz` | **M11.5 PR-5 (ADR-062)** readiness (no auth): probes `store` (the gateway socket) · `llm` (`GET <base_url>/models`) · `config` (a document is present) → `200 {status:"ready"}` / `503 {status:"not_ready"}`. An unconfigured dependency is `skipped` (standalone stays ready). The result is cached (3 s TTL, single-flighted); redirects are not followed; `detail` strings go to authenticated callers only |
| GET/PUT | `/v1/config` | **M11.5 PR-5 (ADR-062)** the service-tier config in the store-gateway's `config` domain. Both operations are token-gated. `PUT` refuses a document carrying a secret-shaped member (`400` with the member's path) or an oversized body (`413`), and answers `501` in the standalone tier (no store) |
| GET | `/v1/config-schema` | the RunConfig surface (for the WebUI) — keys/defaults from `runconfig.py`/flags |
| POST | `/v1/runs` | start a run from `{target, runConfig|mode/goal/describe/planner/budgets/auth, env?}` → `{run_id}` (spawns `agentctl run …`, like the orchestrator). **M9.9 (ADR-047):** also `{mode:"replay"\|"baseline", from_run:"<prior run_id>"}` → re-run / baseline-update that prior run's frozen plan (`agentctl run --replay --plan` / `baseline update --plan`; `from_run` resolves to `runs/control-<id>/{plan.json\|scenario.json}`, traversal-guarded) |
| GET | `/v1/runs/{id}` | status: `{state: running|done|failed, exit_code, artifact_dir}` |
| GET | `/v1/runs` | list recent runs |

**Security (ADR-032):**
- **Bind to `127.0.0.1` by default** (`CONTROL_API_ADDR`, not `0.0.0.0` without explicit opt-in) — spawning
  runs is a sensitive surface (RCE-class if publicly exposed).
- **Bearer token** (`CONTROL_API_TOKEN`) required for mutations (`POST /v1/runs`); `/healthz` is open.
  With no token in env, mutations return **403** (read-only/health only).
- **CORS allowlist** (`CONTROL_API_CORS_ORIGINS`, e.g. `https://alexgromer.github.io,http://localhost:8088`):
  ⇒ **a Pages page can drive a LOCAL control-API** (localhost is mixed-content-exempt + CORS). Empty by
  default (CORS off; same-origin/bundle only).
- Spawn only via the known `agentctl` path + input validation (no arbitrary commands).

## M9.3-tail — chat-front + streaming + artifact-fetch (✅ DELIVERED, ADR-040)

> M9.3's tail (GAP-M9-03/12 + partial GAP-M9-14). The three decisions:

**Chat-front = custom vanilla `docs/chat/index.html` (NOT Open WebUI).** brain is **non-conversational**:
the M7 MCP server exposes only `explore/heal/replay/report` (stdio + host `sampling`), and describe-mode is
strictly **one-shot** (one NL string → one `scenario.json` → exit). Open WebUI needs an OpenAI-compatible
`/v1/chat/completions` OR an mcpo-frontable tool server with host sampling — brain provides neither;
integration = a new heavyweight adapter that breaks the air-gapped ethos. So it's a self-contained sibling of
setup-WebUI: inline style+script, system fonts, no CDN, `file://`-safe; **bilingual** (`data-lang`/`setLang`,
localStorage `sentinel_lang`); an honest "chat-style authoring console" (not multi-turn — the UI says so).
Flow: describe (target + mode `describe|goal|explore` + NL) → `POST /v1/runs` (202) → **SSE** progress stream →
on `done` show/download `scenario.json`/report. Falls back to 2 s polling if SSE is unavailable. Served by the
existing `webui` profile at `:8088/chat/` (no new profile — static under `/app/docs`).

**Streaming = SSE, not WS (ADR-040).** The control-API is extended (stdlib, no new deps):
- `GET /v1/runs/{id}/events` — **SSE, token-gated**: `event: state` (running|done|failed + exit_code),
  `event: log` (the run's stdout/stderr from a capped ring-buffer — replayed on connect + live), terminal
  `event: done`. Run output is captured into a per-run ring-buffer + fanned out to subscribers.
- `GET /v1/runs/{id}/artifact?name=<f>` — **token-gated**, serves a whitelisted file from `artifact_dir`
  (`scenario.json`/`reconcile-report.json`/`report.json`/`report.html`/`plan.json`; guard on `/`·`..`; 404 if absent).
- **Why SSE, not WS:** WebSocket would need a non-stdlib dep / hand-rolled RFC6455 — violating the control-API's
  stdlib-only principle (like the M8 report-service). **GAP-M9-14 PARTIALLY closed:** the server→client live
  channel exists; the extension recorder's client→server channel (WS *or* native-messaging) is an **M9.8-impl** call.
- Security: events/artifact sit behind the same bearer token as mutations (logs/artifacts are more sensitive than
  status); reuses the localhost-bind + CORS allowlist (ADR-032).

**CI templates = `docs/ci-templates/` (✅).** `Jenkinsfile` + `.gitlab-ci.yml` + bilingual `README.md`/`.en.md`.
The exit-code mapping is DERIVED from `brain/events.json` → `exit_codes` (ADR-141; gate
`tests/test_exit_code_surfaces_offline.py`). In CI: 0→success; 1/2→failure; 3/4/5→unstable — 4 and 5
mean WE broke, and a red build in someone else's pipeline would send them to debug an application
that is certainly not at fault. ⚠ The old citation pointed at `cmd/agentctl/main.go:10`, which holds no codes. These are **user**
templates, not our `.github/workflows/`.

**Out of scope (deferred):** a replay-via-control-API endpoint (submit a frozen `scenario.json` for a deterministic
re-run) — minimizes the sensitive spawn surface; the describe→author+run-in-one-shot + show/download loop is already
complete.
