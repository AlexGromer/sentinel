## §0. Что было замерено ДО этой вехи

Веха десять недель числилась «наполовину готовой (ADR-045)». Четыре замера говорят, что именно
существовало:

| Замер | Результат |
|---|---|
| `grep -c 'adapter\|SPI'` по `internal/` и `cmd/` (Go) | **0**. Слово жило в дорожной карте и в одном документе, в продукте — нигде. |
| `brain/llm.py::make_backend` | Ветвление по **двум строковым литералам** провайдера, завершавшееся `log("llm.backend_unknown"); return None`. ADR-045 сделал подключаемой **OpenAI-СОВМЕСТИМОСТЬ** (любой endpoint, говорящий по этому протоколу), а не сам слот провайдера: бэкенд с другим SDK (Bedrock, Vertex native, внутренний шлюз) требовал правки корневого файла. «Опциональный роутер за `LLM_BASE_URL`» — это конфигурация, а не шов. |
| `brain/runconfig.py::_AUTH_ENV` | Литеральный словарь из четырёх записей; `load_run_config` **УДАЛЯЛ** любой под-ключ `auth:`, которого в нём нет. Внешний механизм авторизации не мог даже **ПОЛУЧИТЬ** свою конфигурацию — загрузчик стирал её раньше, чем до неё доходил хоть какой-то код. |
| deploy | Рантайм-шва не было вовсе. `deploy/sentinel/values.yaml` `extraEnv` + хелпер `sentinel.envAllow` — единственный способ развёртывания что-то сказать прогону, и это текст Helm, вычисляемый до старта процесса, а не контракт, через который продукт расширяется. |

Отсюда объём вехи: **обобщить существующее**, а не построить новый слой. Ни одна возможность
продукта не добавляется; добавляется **место**, куда чужой код встаёт без правки нашего.

## §1. Ядро — `brain/adapters.py`

Один реестр, три вида, и **встроенные адаптеры зарегистрированы В НЁМ**, а не рядом с ним.

```
KINDS = (MODEL, AUTH, DEPLOY)          # "model" | "auth" | "deploy"
DEFAULTS = {AUTH: "storage_state", DEPLOY: "local"}
```

| Функция | Смысл |
|---|---|
| `register(kind, adapter, *, replace=False)` | Регистрация. Форма проверяется **здесь**, а не в момент использования: плагин, падающий при первом вызове, падает в чужом CI, и сообщение будет про отсутствующий атрибут, а не про плагин. Повтор имени отклоняется без `replace=True` — иначе поведение прогона зависело бы от порядка импорта. |
| `get(kind, name)` | Адаптер или `None`. |
| `require(kind, name)` | Адаптер или `ValueError`, **перечисляющий доступные имена** (обычная причина промаха — опечатка или незагруженный плагин; обе лечатся видом настоящих имён). |
| `names(kind)` | Отсортированные имена. **Единственный перечень; второй копии нет нигде** — из него выводятся все обходы гейта (`docs/DEVELOPMENT.md` §0, принцип 5). |
| `unregister(kind, name)` | Снятие. |
| `load_from_env(env=None)` | Импорт модулей из `SENTINEL_ADAPTERS`. Идемпотентно. |

**Почему `MODEL` нет в `DEFAULTS`:** его умолчание — свойство не блока конфигурации, а правила
предпочтения окружения в `brain/llm.py` (`LLM_BACKEND_<ROLE>` > `LLM_BACKEND` > `anthropic`).
Дублирование создало бы второе место, где ему дрейфовать.

### Обнаружение

`SENTINEL_ADAPTERS` перечисляет **импортируемые модули** (через запятую или `os.pathsep`); импорт
модуля и есть регистрация его адаптеров.

> **Метаданные entry-points отклонены:** они требуют, чтобы плагин был установлен через pip в то же
> окружение, а продукт штатно запускается из дерева исходников с `uv sync --frozen`; половина
> развёртываний не смогла бы этим воспользоваться.

### Отказ расщеплён НАМЕРЕННО

Две половины отказа имеют разные последствия, поэтому и обрабатываются они по-разному:

- **Модуль из `SENTINEL_ADAPTERS` не импортируется** → `load_from_env` **БРОСАЕТ**.
  `make_backend` уже оборачивает построение провайдера и превращает это в
  `llm.provider_unavailable` + откат на эвристику (прогон без ИИ, **объявленный**);
  `load_run_config`/`apply_run_config` выпускают ошибку наружу как конфигурационную → **exit 3**.
  Молчания нет ни в одном из путей.
- **Запрошен адаптер ПО ИМЕНИ, которого нет** → `ValueError` **всегда**, в обоих путях. Опечатка в
  `auth: {adapter: …}` не имеет права откатиться на «без авторизации»: это ровно та форма отказа,
  за которую проект уже платил — прогон, который выглядит удачным и не сделал того, что просили.

## §2. Вид `MODEL` — провайдер как адаптер

```python
class ModelAdapter(Protocol):
    name: str
    def make(self, spec: ModelSpec) -> Optional[LLMBackend]: ...
```

`ModelSpec` — **замороженный** датакласс с уже разрешённым окружением:
`{role, provider, model, base_url, api_key, supports_vision, supports_structured}`.

Адаптер **не имеет права** читать `LLM_*` сам: правило предпочтения «роль, затем глобально»
(`LLM_<KEY>_<ROLE>` > `LLM_<KEY>`) — документированное правило продукта, и внешний адаптер, его
переписывающий, стал бы второй реализацией, свободной дрейфовать. `spec.api_key` несёт **только**
явно заданный `LLM_API_KEY[_ROLE]`; провайдер-специфичный откат (`ANTHROPIC_API_KEY`,
`OPENAI_API_KEY`) остаётся у адаптера, который знает провайдера, — это ровно то, что знает он и не
знает общий резолвер.

**Встроенные `anthropic` и `openai` зарегистрированы как обычные адаптеры** (`brain/llm.py`,
`_AnthropicAdapter` / `_OpenAICompatAdapter`), поэтому у `make_backend` **ровно один** путь
провайдера. Шов, по которому ходит только чужой код, — это шов, который ничто в CI не проходит.

`sampling` (MCP, ADR-020) разрешается **до** реестра и адаптером не является: это свойство того, КАК
запущен процесс, а не настроенный провайдер, и плагин с именем `sampling` не должен иметь
возможности его вытеснить.

### Пример: внешний провайдер

```python
# mycorp_sentinel/adapters.py
from brain import adapters

class BedrockAdapter:
    name = "bedrock"
    def make(self, spec):
        import boto3
        return MyBedrockBackend(spec.model, region=spec.base_url or "eu-central-1")

adapters.register(adapters.MODEL, BedrockAdapter())
```

```bash
SENTINEL_ADAPTERS=mycorp_sentinel.adapters \
LLM_BACKEND=bedrock LLM_MODEL=anthropic.claude-sonnet-4-6 \
  ./bin/agentctl run --target https://app.example
```

## §3. Виды `AUTH` и `DEPLOY` — декларативный блок → окружение

```python
class EnvAdapter(Protocol):
    name: str
    keys: frozenset                                   # принимаемые под-ключи
    def env(self, spec: Mapping) -> Mapping[str, str]: ...
```

`env()` — **чистая функция**: возвращает отображение и **не трогает окружение процесса**. Именно это
держит предпочтение в одном месте — `brain/runconfig.py::_apply_block` прогоняет результат через
`_overridable`, поэтому явный флаг бьёт файл, **кем бы адаптер ни был написан**. Адаптер, способный
писать в окружение напрямую, был бы адаптером, способным молча перебить флаг оператора.

`EnvBlockAdapter` — база для типичного случая (таблица «под-ключ → переменная»). `keys`
**ВЫВОДИТСЯ** из `_ENV` в `__init_subclass__`, а не пишется рядом: рукописный список-спутник
отказывает в ту сторону, которую не видно — лишняя запись падает громко, а **пропущенная молчит**, и
ключ тогда удаляется загрузчиком раньше, чем его кто-либо заметит.

### Форма блока в RunConfig

```yaml
auth:
  adapter: storage_state          # необязательно; умолчание — то, что было до SPI
  storage_state: /run/state.json
  pw_no_trace: true

deploy:
  adapter: local                  # необязательно
  store_addr: gateway:50051
  otel_endpoint: http://otel:4317
```

Отсутствие `adapter:` выбирает адаптер, который поставлялся, — **любой RunConfig, написанный до этой
вехи, значит ровно то же, что значил** (в том числе блоки, которые `control-api` пишет сам,
`cmd/control-api/main.go::appendRunFlags`, — там `adapter:` не ставится). Изменилось другое: какие
под-ключи переживают загрузчик — теперь это `keys` **выбранного** адаптера, а не литерал в
`runconfig.py`.

### Референсный `AUTH` — `storage_state` (M9.1, ADR-026, без изменений)

| Под-ключ | Переменная | Роль в потоке «логин-как-тест» |
|---|---|---|
| `storage_state` | `STORAGE_STATE` | прод-прогон: сессия предзагружена, пароль не вводится вовсе |
| `storage_state_save` | `STORAGE_STATE_SAVE` | логин-прогон: куда сохранить сессию после `exit 0` |
| `login_plan` | `PLAN_FILE` | план логина |
| `pw_no_trace` | `PW_NO_TRACE` | нормализуется в `1`/`0` |

Референсом намеренно выбрано **то, что уже работает**: смысл вехи — **стабильный** шов, а
стабильность шва показывается тем, что он несёт вещь, которая уже работала, а не новую.

> ⚠ **`pw_no_trace` — не режим, а fail-closed предохранитель ввода секрета** с двумя независимыми
> точками принуждения (`browser.fill` бросает при активной трассировке — `pw-executor/src/server.ts`;
> replay с `secretRef` даёт **exit 3** до старта — `brain/__main__.py`). Адаптер, ставящий его в
> `0`, **снимает защиту**, а не настраивает режим. По той же причине `brain/observe.py` эту
> переменную не трогает вовсе.

### Референсный `DEPLOY` — `local`

**Почему именно эти три ключа, а не очевидные.** `ARTIFACT_DIR` и `PW_EXECUTOR_CMD` выглядят как
проводка развёртывания и ею **не являются**: `cmd/agentctl/main.go` выдаёт **оба** на каждый
порождаемый прогон (`ARTIFACT_DIR=`+dir встречается на девяти путях запуска, `PW_EXECUTOR_CMD=`+pwExec
— на пути исполнителя), поэтому значение из RunConfig проигрывало бы явному на **каждом** реальном
вызове, и ключ был бы украшением. Ниже — три, которые brain читает и которые agentctl **не**
выставляет:

| Под-ключ | Переменная | Кто читает |
|---|---|---|
| `store_addr` | `STORE_ADDR` | `brain/store.py::make_store` — gRPC-шлюз вместо `LocalStore`; agentctl задаёт её только когда сам поднимает или наследует шлюз |
| `otel_endpoint` | `OTEL_EXPORTER_OTLP_ENDPOINT` | `brain/otel.py` — не задана ⇒ no-op tracer |
| `checkpoint_dsn` | `CHECKPOINT_DSN` | `brain/__main__.py::_checkpointer` — Postgres вместо SQLite (мульти-раннер K3s) |

Адаптер `kubernetes` или `compose` выводит те же три из чарта или downward API и **заменяет** этот —
ради этой замены шов и существует. Сегодня Helm-чарт передаёт их вручную через `extraEnv` +
`sentinel.envAllow` (`deploy/sentinel/templates/`): это работает и **невидимо для продукта**;
наименование делает его контрактом.

## §4. Граница лицензии (ADR-056 §2 строка 42)

Репозиторий под **Apache-2.0**, и Apache **необратим**. SPI и его референсные адаптеры — открытый
каркас (open-core framework). Корпоративная авторизация — **Keycloak / OIDC / Vault / SSO / RBAC /
multi-user** — цепляется к этому SPI **СНАРУЖИ** и сюда не коммитится никогда; она числится как
`[M-COMMERCIAL-auth]`.

Граница **ПРОВЕРЯЕТСЯ, а не записана**: `tests/test_adapter_spi_offline.py` обходит имена, которые
регистрирует этот репозиторий, и краснеет, если хоть одно говорит на словаре корпоративной
авторизации. Обход **выведен** из `adapters.names(kind)`, поэтому новый адаптер попадает под правило
сам по себе.

## §5. Гейт (offline, без браузера/сети/модели)

`tests/test_adapter_spi_offline.py` — **тринадцать групп проверок, все поведенческие**: адаптеры, объявленные в
самом гейте, регистрируются в **настоящем** реестре, после чего вызываются **поставляемые** точки
входа `brain.llm.make_backend(role)` и `brain.runconfig.load_run_config`/`apply_run_config`.
**Ни одна проверка не читает исходник**: утверждение о ФОРМЕ кода — суррогат, мутации проходят его
насквозь, и в этом проекте это замерено многократно.

Что закреплено:

1. Реестр отклоняет сломанный адаптер **при регистрации** (нет имени · нет метода · метод не
   вызываемый · неизвестный вид · повтор имени).
2. `require` перечисляет доступные имена в сообщении.
3. **Чужой провайдер реально подхватывается `make_backend`**, и `ModelSpec` доносит роль, провайдера,
   разрешённое по предпочтению имя модели, адрес, ключ и флаги.
4. **Поставляемые провайдеры идут тем же путём**, и их прежние отказы (нет ключа · нет ни ключа, ни
   адреса · неизвестный провайдер) не изменились.
5. Неимпортируемый плагин **деградирует** прогон через `make_backend` и **не роняет** его.
6. **Чужой auth-адаптер получает под-ключ, который прежний загрузчик удалял.** ⚠ Эта проверка
   краснеет на дереве до M9.7 — она и есть замер, определивший веху.
7. Неизвестное имя адаптера — **конфигурационная ошибка (exit 3)**, а не молчаливый откат.
8. Неимпортируемый плагин на пути RunConfig — **жёсткая** ошибка (вторая половина расщепления).
9. Референсный `auth` воспроизводит M9.1 дословно, включая нормализацию `pw_no_trace` и
   предпочтение явного окружения.
10. Референсный `deploy` доводит три переменные, и унаследованный `STORE_ADDR` по-прежнему
    выигрывает.
11. **Выведенный обход**: для каждого поставляемого env-адаптера **каждый** объявленный им под-ключ
    переживает загрузчик и доходит до переменной. **Пол** — не меньше двух адаптеров и не меньше
    семи под-ключей: обход, переставший что-либо находить, пройдёт идеально над пустым множеством, и
    это единственное, чего сам вывод не ловит.
12. **Граница лицензии** (§4).
13. **Сквозной замер кода возврата:** настоящий `python -m brain` с `RUN_CONFIG`, называющим несуществующий адаптер, отдаёт **exit 3** и говорит, какой адаптер и какие есть. Отказ случается до порождения исполнителя, поэтому проверка остаётся офлайновой. Чтение исходника тут было бы суррогатом: превращение `ValueError` в `3` живёт в `try/except` за сотни строк от разбора, и правка любого конца оставила бы утверждение о форме зелёным.

**Мутации: 13 поставлено, 13 убито, все скомпилировались.** Каждая ломает ровно одно свойство:
фильтр под-ключей возвращён к прежнему литеральному словарю · `make_backend` игнорирует реестр ·
`keys` перестаёт выводиться из `_ENV` · значение пишется мимо проверки предпочтения · неизвестное
имя молча откатывается · ошибка импорта проглатывается · булевы под-ключи не нормализуются ·
enterprise-адаптер зарегистрирован в дереве · `register` не проверяет вызываемость · `ModelSpec`
теряет предпочтение по роли · `names()` пустеет (пол) · повтор регистрации молча перетирает · неверный RunConfig перестаёт быть `exit 3`.

Прочие гейты: весь offline-сьют зелёный
(`for f in tests/test_*_offline.py; do PYTHONPATH="$PWD" .venv/bin/python "$f"; done` — число файлов
здесь намеренно не дублируется, оно выводится обходом) · `go build ./...` · `go vet ./...` —
Go не менялся.

## §6. Вне объёма

- **Корпоративная авторизация** — `[M-COMMERCIAL-auth]`, §4. Необратимо.
- **Мастер настройки (`/v1/config-schema`, `cmd/control-api/main.go`)** не показывает выбор
  адаптера: он пишет `auth:` без `adapter:`, что значит умолчание и поведение, которое было. Проводка
  выбора в интерфейс — отдельная задача (принцип 6, `docs/DEVELOPMENT.md` §0: возможность достижима
  тремя путями), заведена как `[M9.7-UI-ADAPTER-PICK]`.
- **Vault/Helm Secret-плумбинг** (`docs/M9.1_CONTRACT.md` §4 обещал его этой вехе): чарт умеет
  `extraSecretEnv` → `secretKeyRef` с M11.3/ADR-035, чего хватает референсному пути; сам
  Vault-адаптер — коммерческий и живёт снаружи.
