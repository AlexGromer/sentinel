## §0. What was measured BEFORE this milestone

The milestone had been "half done (ADR-045)" for ten weeks. Four measurements say what actually
existed:

| Measurement | Result |
|---|---|
| `grep -c 'adapter\|SPI'` over `internal/` and `cmd/` (Go) | **0**. The word lived in the roadmap and in one document; nowhere in the product. |
| `brain/llm.py::make_backend` | An if/elif over **two literal provider names**, ending in `log("llm.backend_unknown"); return None`. What ADR-045 made pluggable was OpenAI-**COMPATIBILITY** (any endpoint speaking that wire), not the provider slot: a backend with a different SDK (Bedrock, Vertex native, an in-house gateway) required editing the core file. "Optional router behind `LLM_BASE_URL`" is a configuration, not a seam. |
| `brain/runconfig.py::_AUTH_ENV` | A four-entry literal dict, and `load_run_config` **DROPPED** every `auth:` sub-key outside it. An out-of-tree auth mechanism could not even **RECEIVE** its configuration — the loader deleted it before any code could look. |
| deploy | No runtime seam at all. `deploy/sentinel/values.yaml` `extraEnv` plus the `sentinel.envAllow` helper is the only way a deployment speaks to a run, and that is Helm text evaluated before the process starts, not a contract the product can be extended through. |

Hence the scope: **generalize what exists**, do not build a new layer. No product capability is
added; what is added is the **place** where third-party code stands without editing ours.

## §1. The core — `brain/adapters.py`

One registry, three kinds, and the **built-ins registered INTO it** rather than beside it.

```
KINDS = (MODEL, AUTH, DEPLOY)          # "model" | "auth" | "deploy"
DEFAULTS = {AUTH: "storage_state", DEPLOY: "local"}
```

| Function | Meaning |
|---|---|
| `register(kind, adapter, *, replace=False)` | Registration. The shape is checked **here**, not at first use: a plugin that fails on first use fails inside somebody else's CI, and the message is about a missing attribute rather than about the plugin. A duplicate name is refused without `replace=True` — otherwise a run's behaviour would depend on import order. |
| `get(kind, name)` | The adapter, or `None`. |
| `require(kind, name)` | The adapter, or `ValueError` **listing the available names** (the usual cause of a miss is a typo or a plugin that never loaded; both are answered by seeing the real names). |
| `names(kind)` | Sorted names. **The only such list; there is no second copy anywhere** — every walk in the gate is derived from it (`docs/DEVELOPMENT.md` §0, principle 5). |
| `unregister(kind, name)` | Removal. |
| `load_from_env(env=None)` | Imports the modules named by `SENTINEL_ADAPTERS`. Idempotent. |

**Why `MODEL` is absent from `DEFAULTS`:** its default is not a property of a config block but of the
env precedence rule in `brain/llm.py` (`LLM_BACKEND_<ROLE>` > `LLM_BACKEND` > `anthropic`).
Duplicating it here would create a second place for it to drift.

### Discovery

`SENTINEL_ADAPTERS` names **importable modules** (comma- or `os.pathsep`-separated); importing a
module is what registers its adapters.

> **Entry-point metadata was rejected:** it requires the plugin to be pip-installed into the same
> environment, and this product routinely runs from a source tree with `uv sync --frozen`, so half
> the deployments could not use it.

### Failure is split DELIBERATELY

The two halves of failure have different consequences, so they are handled differently:

- **A module in `SENTINEL_ADAPTERS` will not import** → `load_from_env` **RAISES**. `make_backend`
  already wraps provider construction and turns this into `llm.provider_unavailable` + the heuristic
  fallback (a run without AI, **announced**); `load_run_config`/`apply_run_config` let it out as a
  config error → **exit 3**. Neither path is silent.
- **An adapter is asked for BY NAME and is not registered** → `ValueError`, **always**, in both
  paths. A typo in `auth: {adapter: …}` must not fall back to "no auth": that is exactly the shape of
  failure this project keeps paying for — a run that looks successful and did not do the thing.

## §2. Kind `MODEL` — a provider as an adapter

```python
class ModelAdapter(Protocol):
    name: str
    def make(self, spec: ModelSpec) -> Optional[LLMBackend]: ...
```

`ModelSpec` is a **frozen** dataclass carrying the already-resolved environment:
`{role, provider, model, base_url, api_key, supports_vision, supports_structured}`.

An adapter **must not** read `LLM_*` itself: the role-then-global precedence
(`LLM_<KEY>_<ROLE>` > `LLM_<KEY>`) is a documented product rule, and a third-party adapter
re-implementing it would be a second implementation free to drift. `spec.api_key` carries **only**
the explicitly configured `LLM_API_KEY[_ROLE]`; the provider-specific fallback (`ANTHROPIC_API_KEY`,
`OPENAI_API_KEY`) stays with the adapter that knows the provider — that is precisely the thing it
knows and the generic resolver does not.

**The built-in `anthropic` and `openai` are registered as ordinary adapters** (`brain/llm.py`,
`_AnthropicAdapter` / `_OpenAICompatAdapter`), so `make_backend` has **exactly one** provider path.
A seam only third-party code travels is a seam nothing in CI exercises.

`sampling` (MCP, ADR-020) is resolved **before** the registry and is not an adapter: it is a property
of HOW the process is running rather than a configured provider, and a plugin named `sampling` must
not be able to displace it.

### Example: an out-of-tree provider

```python
# mycorp_sentinel/adapters.py
from brain import adapters

class BedrockAdapter:
    name = "bedrock"
    def make(self, spec):
        import boto3
        return MyBedrockBackend(spec.model, region=spec.base_url or "eu-central-1")

adapters.register(adapters.MODEL, BedrockAdapter())
```

```bash
SENTINEL_ADAPTERS=mycorp_sentinel.adapters \
LLM_BACKEND=bedrock LLM_MODEL=anthropic.claude-sonnet-4-6 \
  ./bin/agentctl run --target https://app.example
```

## §3. Kinds `AUTH` and `DEPLOY` — a declarative block → environment

```python
class EnvAdapter(Protocol):
    name: str
    keys: frozenset                                   # accepted sub-keys
    def env(self, spec: Mapping) -> Mapping[str, str]: ...
```

`env()` is a **pure function**: it returns a mapping and **does not touch the process environment**.
That is what keeps precedence in one place — `brain/runconfig.py::_apply_block` applies the result
through `_overridable`, so an explicit flag beats the file **no matter who wrote the adapter**. An
adapter able to write env directly would be an adapter able to quietly outrank the operator's flag.

`EnvBlockAdapter` is the base for the common case (a "sub-key → variable" table). `keys` is
**DERIVED** from `_ENV` in `__init_subclass__` rather than written beside it: a hand-kept companion
list fails in the direction you cannot see — a stale entry breaks loudly, a **missing** one is
silence, and the key is then dropped by the loader before anyone notices.

### The RunConfig block shape

```yaml
auth:
  adapter: storage_state          # optional; the default is what shipped before the SPI
  storage_state: /run/state.json
  pw_no_trace: true

deploy:
  adapter: local                  # optional
  store_addr: gateway:50051
  otel_endpoint: http://otel:4317
```

Omitting `adapter:` selects the adapter that shipped, so **every RunConfig written before this
milestone means exactly what it meant** — including the blocks `control-api` writes itself
(`cmd/control-api/main.go::appendRunFlags`, which sets no `adapter:`). What changed is which sub-keys
survive the loader: now the **chosen** adapter's `keys`, not a literal in `runconfig.py`.

### Reference `AUTH` — `storage_state` (M9.1, ADR-026, unchanged)

| Sub-key | Variable | Role in the login-as-test flow |
|---|---|---|
| `storage_state` | `STORAGE_STATE` | production run: the session is pre-loaded, the password is never typed |
| `storage_state_save` | `STORAGE_STATE_SAVE` | login run: where to persist the session after `exit 0` |
| `login_plan` | `PLAN_FILE` | the login plan |
| `pw_no_trace` | `PW_NO_TRACE` | normalized to `1`/`0` |

The reference is deliberately **the thing that already works**: the point of this milestone is a
**stable** seam, and a seam is shown to be stable by carrying what already worked, not something new.

> ⚠ **`pw_no_trace` is not a mode but a fail-closed secret guard**, with two independent enforcement
> points (`browser.fill` throws while tracing is active — `pw-executor/src/server.ts`; a replay
> carrying a `secretRef` exits 3 before starting — `brain/__main__.py`). An adapter setting it to `0`
> is **removing a protection**, not configuring a mode. For the same reason `brain/observe.py` never
> touches this variable.

### Reference `DEPLOY` — `local`

**Why these three keys and not the obvious ones.** `ARTIFACT_DIR` and `PW_EXECUTOR_CMD` look like
deployment wiring and are not: `cmd/agentctl/main.go` emits **both** for every run it spawns
(`ARTIFACT_DIR=`+dir appears on nine spawn paths, `PW_EXECUTOR_CMD=`+pwExec on the executor path), so
a RunConfig value for either would lose to the explicit value on **every** real invocation and the
key would be decoration. Below are three the brain reads and agentctl does **not** pre-set:

| Sub-key | Variable | Reader |
|---|---|---|
| `store_addr` | `STORE_ADDR` | `brain/store.py::make_store` — the gRPC gateway instead of `LocalStore`; agentctl sets it only when it starts or inherits a gateway |
| `otel_endpoint` | `OTEL_EXPORTER_OTLP_ENDPOINT` | `brain/otel.py` — unset means a no-op tracer |
| `checkpoint_dsn` | `CHECKPOINT_DSN` | `brain/__main__.py::_checkpointer` — Postgres instead of SQLite (multi-runner K3s) |

A `kubernetes` or `compose` adapter derives the same three from a chart or the downward API and
**replaces** this one — that substitution is the whole reason the seam exists. Today the Helm chart
passes them by hand through `extraEnv` + `sentinel.envAllow` (`deploy/sentinel/templates/`), which
works and is **invisible to the product**; naming it makes it a contract.

## §4. The licence boundary (ADR-056 §2 row 42)

This repository is **Apache-2.0**, and Apache **cannot be taken back**. The SPI and its reference
adapters are the open-core framework. Enterprise auth — **Keycloak / OIDC / Vault / SSO / RBAC /
multi-user** — attaches to this SPI **FROM OUTSIDE** and is never committed here; it is tracked as
`[M-COMMERCIAL-auth]`.

The boundary is **CHECKED, not merely written down**: `tests/test_adapter_spi_offline.py` walks the
names this repository registers and reddens if one of them speaks enterprise-auth vocabulary. The
walk is **derived** from `adapters.names(kind)`, so a new adapter falls under the rule automatically.

## §5. The gate (offline — no browser, no network, no model)

`tests/test_adapter_spi_offline.py` — **thirteen groups of checks, all behavioural**: adapters declared
in the gate itself are registered into the **real** registry, and the **shipped** entry points
`brain.llm.make_backend(role)` and `brain.runconfig.load_run_config`/`apply_run_config` are then
called for real. **No check reads a source file**: an assertion about the SHAPE of code is a
surrogate — mutations pass straight through one, which this project has measured repeatedly.

What is pinned:

1. The registry refuses a broken adapter **at registration** (no name · no method · method not
   callable · unknown kind · duplicate name).
2. `require` lists the available names in its message.
3. **A third-party provider really drives `make_backend`**, and `ModelSpec` carries the role, the
   provider, the precedence-resolved model name, the base URL, the key and the flags.
4. **The shipped providers travel the same path**, and their previous refusals (no key · neither key
   nor base URL · unknown provider) are unchanged.
5. An unimportable plugin **degrades** the run through `make_backend` and does **not** crash it.
6. **A third-party auth adapter receives the sub-key the old loader deleted.** ⚠ This check reddens
   on the pre-M9.7 tree — it IS the measurement that defines the milestone.
7. An unknown adapter name is a **config error (exit 3)**, never a silent fallback.
8. An unimportable plugin on the RunConfig path is a **hard** error (the other half of the split).
9. The reference `auth` reproduces M9.1 verbatim, including `pw_no_trace` normalization and the
   precedence of an explicit environment.
10. The reference `deploy` lands its three variables, and an inherited `STORE_ADDR` still wins.
11. **Derived walk**: for every shipped env adapter, **every** sub-key it declares survives the
    loader and reaches a variable. **Floors** — at least two adapters and at least seven sub-keys: a
    walk that has stopped finding anything passes perfectly over an empty set, and that is the one
    thing derivation cannot catch by itself.
12. **The licence boundary** (§4).
13. **The exit code, measured end to end:** a real `python -m brain` with a `RUN_CONFIG` naming an adapter that does not exist returns **exit 3** and says which adapter and which ones exist. The refusal happens before any executor is spawned, so the check stays offline. Reading the source here would be a surrogate: the ValueError→3 mapping lives in a try/except hundreds of lines from the parse, and a change at either end would leave a source assertion green.

**Mutations: thirteen applied, thirteen killed, all compiled.** Each breaks exactly one property: the
sub-key filter reverted to the old literal dict · `make_backend` ignores the registry · `keys` stops
being derived from `_ENV` · a value is written past the precedence check · an unknown name silently
falls back · an import error is swallowed · boolean sub-keys stop being normalized · an enterprise
adapter is registered in-tree · `register` stops checking callability · `ModelSpec` loses the
per-role precedence · `names()` goes empty (the floor) · a duplicate registration silently
overwrites · an invalid RunConfig stops being `exit 3`.

Other gates: the whole offline suite is green
(`for f in tests/test_*_offline.py; do PYTHONPATH="$PWD" .venv/bin/python "$f"; done` — the file count
is deliberately not duplicated here; it is derived by the walk) · `go build ./...` · `go vet ./...` —
Go is unchanged.

## §6. Out of scope

- **Enterprise auth** — `[M-COMMERCIAL-auth]`, §4. Irreversible.
- **The setup wizard (`/v1/config-schema`, `cmd/control-api/main.go`)** does not surface the adapter
  choice: it writes `auth:` with no `adapter:`, which means the default and the behaviour that
  already existed. Wiring the choice into the interface is a separate task (principle 6,
  `docs/DEVELOPMENT.md` §0: a capability is reachable three ways), filed as
  `[M9.7-UI-ADAPTER-PICK]`.
- **Vault/Helm secret plumbing** (`docs/M9.1_CONTRACT.md` §4 promised it to this milestone): the
  chart has had `extraSecretEnv` → `secretKeyRef` since M11.3/ADR-035, which is enough for the
  reference path; the Vault adapter itself is commercial and lives outside.
