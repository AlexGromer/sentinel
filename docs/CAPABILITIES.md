# Что этот инструмент умеет

> 🌐 **Русский** (основная версия) · [English](CAPABILITIES.en.md)

Каталог реально работающих возможностей, до которых трудно добраться, потому что раньше их никто не называл (класс LiteLLM: код есть, найти нельзя). Источник истины — [`capabilities.json`](capabilities.json); гейт `tests/test_capabilities_offline.py` проверяет, что путь доступа каждой записи каталога реально резолвится в коде (подкоманда есть в диспетчере `agentctl`, маршрут зарегистрирован в control-api, вью принимается роутером хаба), поэтому каталог не может обещать то, чего в продукте нет. Таблицы ниже — человеческая проекция того же каталога и не претендуют на полноту; полный и всегда актуальный список рендерит вью «Инструменты» в самом приложении и [`capabilities.json`](capabilities.json).

## Интеграции

| Возможность | Как добраться |
|---|---|
| **OpenAI-совместимый эндпоинт ⭐** | POST /v1/chat/completions — подключите любой OpenAI-клиент (Open WebUI, SDK, curl) к продукту. |

## CLI (`agentctl`)

| Возможность | Как добраться |
|---|---|
| **Экспорт в @playwright/test ⭐** | agentctl export-spec --plan <plan.json> — замороженный план -> .spec.ts; путь миграции к Playwright. |
| **Отчёты (html/json/junit/prom)** | agentctl report --run <run-dir> — единственный источник report.html, report.json, junit.xml, metrics.prom. |
| **Калибровка самопочинки** | agentctl calibrate — точность самопочинки по стратегиям + вердикты тождества. |
| **Зачистка чужого текста из БД** | agentctl purge-store --tables <..> --yes — явная зачистка накопленного чужого текста (ADR-100). |
| **Редакция трейса** | agentctl redact-trace --trace <trace.zip> — вычистить введённые значения и секреты из трейса (ADR-098). |
| **Удаление прогонов, копию которых человек уже унёс** | agentctl sweep-downloaded [--dry-run] --yes — удаляет весь каталог прогона с маркером downloaded.json (ADR-103); необратимо, поэтому без --yes отказывается, а --dry-run считает, ничего не трогая. |

## HTTP API

| Возможность | Как добраться |
|---|---|
| **Библиотека сценариев** | GET/DELETE /v1/scenarios — сохранённые сценарии как переиспользуемые активы. |
| **Продвижение сценария в тест** | POST /v1/tests/promote — превратить сценарий в именованный тест. |
| **Метрики и тренды** | GET /v1/results, GET /v1/trends — исходы прогонов и их динамика, нативно в UI (ADR-051). |
| **Серверная фильтрация логов** | GET /v1/runs/{id}/logs — фильтр по уровню/источнику/категории/модулю/коду. |
| **Конфиг через API + схема** | GET/PUT /v1/config, GET /v1/config-schema — служебная конфигурация и её схема (ADR-060/062). |

## Наблюдаемость

| Возможность | Как добраться |
|---|---|
| **Журнал сервиса ⭐** | Что делал сам инструмент: входы и неудачные входы, аккаунты, правка настроек, отказы в доступе, старт и остановка сервисов. Обычный аккаунт видит свои события, админ и машинный токен — все (HEALTH-005). Тремя способами: GET /v1/service-log · `agentctl service-log [--lvl warn --svc control-api --actor alice]` · вкладка «Журнал сервиса» рядом с «Логи» — тот же рендер и тот же каталог сообщений, а частичный вид называет себя частичным, а не выглядит полным. |
| **Уничтожение записей журнала** | agentctl purge-service --yes [--older-than 720h] — счётчики вместо содержимого; автоматической зачистки нет, и чистка пишет о себе (service.log_purged). |
| **Агрегатный Prometheus-скрейп по прогонам** | GET /metrics — агрегат по прогонам вызывающего (машинный токен/развёртывание без аккаунтов видит все), метка run на каждой серии, # HELP/# TYPE по семейству, честные runs_included/runs_omitted; agentctl metrics — тот же скрейп из терминала (ADR-119, заменяет удалённый cmd/report-service). |

## Рантайм и режимы

| Возможность | Как добраться |
|---|---|
| **Подключение к вашему Chrome (CDP) ⭐** | PW_CDP_ENDPOINT=http://localhost:9222 — инструмент работает в ВАШЕМ Chrome и под вашим входом: он переиспользует вашу сессию, но открывает СВОЮ вкладку и закрывает её за собой; ваши вкладки не читаются и ими не управляют (ADR-037, поправлено ADR-128). |
| **Перехват живого прогона руками ⭐** | GET /v1/stream (WS) — перехватить идущий прогон, поводить руками, вернуть управление. |
| **Живое видео, привязанное к прогону** | GET /v1/live/status\|frame.jpg\|mjpeg?run_id=<id>, agentctl live status\|frame\|stream --run-id <id> — названный прогон получает свою страницу или отказ с причиной, не чужую картинку; без run_id — прежний режим, честно помеченный scoped:false (ADR-121). |
| **Выбор режима наблюдения прогона** | GET /v1/config-schema (режимы off/frames/stream/human/record, дефолт и цена каждого) + POST /v1/runs (observe) + agentctl run --observe <режим> + та же форма прогона в хабе. Все пять режимов ИСПОЛНЯЮТСЯ (human — ADR-120, record — ADR-125), список not_yet пуст. Остались два отказа, и оба про СОЧЕТАНИЕ: украшенный режим не смешивается со снятием эталона, а record невозможен над CDP-attach. |
| **Видеозапись прогона** | observe=record пишет `runs/<id>/video.webm`; забирается как обычный артефакт (GET /v1/runs/{id}/artifact?name=video.webm, agentctl runs artifact) и проигрывается в панели артефактов хаба. ⚠ Запись С КУРСОРОМ, поэтому МЕНЯЕТ ТАЙМИНГ и эталоном быть не может; ⚠ невозможна над CDP-attach — отклоняется до старта. По умолчанию сохраняется только при незелёном прогоне, SENTINEL_VIDEO_ALWAYS=1 оставляет всегда. Сборщик её НЕ забирает: пиксели не редактируются. |
| **Мозг как MCP-сервер ⭐** | RUN_MODE=mcp-server — поднять мозг как MCP-сервер (tools/list + sampling). |
| **Вход один раз (login-as-test) ⭐** | STORAGE_STATE / STORAGE_STATE_SAVE — войти один раз, дальше прогоны стартуют авторизованными; пароль через secretRef. |
| **Многоходовой чат-авторинг** | RUN_MODE=chat (agentctl run --mode chat --conversation-id <id>) — авторинг сценария диалогом. |
| **Управление вкладками** | browser.tabs / switchTab — многовкладочные и мультистраничные сценарии (M9.4). |
| **Скачивание трейса прогона** | GET /v1/runs/{id}/artifact?name=trace.zip — трейс упавшего прогона доступен без доступа к серверу (ADR-099). |
| **Аллоулист окружения** | SENTINEL_ENV_ALLOWLIST — что из окружения хоста доходит до мозга; активен по умолчанию (ADR-035). |
| **Токен-бюджеты** | PLAN_TOKEN_LIMIT / HEAL_TOKEN_LIMIT / TOTAL_TOKEN_LIMIT — потолки трат; исчерпание = мягкая деградация, не отказ (ADR-021). |
| **Отключить скриншоты трейса** | SENTINEL_TRACE_SCREENSHOTS=0 — не записывать кадры (ADR-098 чистит текст, но не пиксели). |
| **Готовые фикстуры «попробовать сейчас»** | testdata/fixtures/l1..l7 — прогнать против встроенной страницы без сети (file://). |

## Развёртывание

| Возможность | Как добраться |
|---|---|
| **Готовый Helm-чарт ⭐** | deploy/sentinel/ — разверните в Kubernetes; шаблоны, values и секреты уже написаны. |
| **Установка без чекаута ⭐** | install.sh — ставит агент по checksum + cosign, без клонирования репозитория. |
| **Air-gapped-бандл со всем UI ⭐** | scripts/build-airgap-bundle.sh — поставка кладёт весь браузерный UI, работает без сети. |
| **Windows как клиент** | install.ps1 — ставит `agentctl.exe` нативно, без admin. Прогон при этом требует Python/uv + Node + браузеры на хосте, поэтому поддерживаемый путь — `agentctl` к control-API в контейнере или на другой машине (ADR-110). |
| **Локальная модель (ollama)** | docker compose --profile ollama up -d ollama — локальный OpenAI-совместимый эндпоинт моделей. |
| **Роутер моделей (LiteLLM)** | docker compose --profile litellm up -d litellm — роутер поверх многих провайдеров за LLM_BASE_URL (ADR-045). |
| **Браузерный UI (webui)** | docker compose up — хаб и мастер раздаются локально на :8088, без флагов. |
| **Постоянное хранилище (store)** | docker compose up — store-gateway поднимается и подключается сам; control-api уже указывает на него (ADR-050). |
