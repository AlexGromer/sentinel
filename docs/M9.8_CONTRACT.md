# Контракт M9.8 — браузерное расширение + co-pilot takeover (ДИЗАЙН)

> 🌐 **Русский** (основная версия) · [English](M9.8_CONTRACT.en.md)

> **Статус**: **Design-first** — контракт; **реализация ОТЛОЖЕНА** · **Дата**: 2026-06-28
> **Покрывает**: M9.8 (GAP-M9-07 «ветка-2» = §F4 co-pilot) · опирается на M9 freeze (ADR-024) + M9.6 CDP-attach (ADR-037) · вводит **ADR-038** (архитектура+транспорт) + **ADR-039** (takeover/return)
> **Блокеры реализации:** M9.3-живой-канал (GAP-M9-03) · рекордер (GAP-M9-13) · стриминг-транспорт (GAP-M9-14) · takeover-протокол (GAP-M9-15). Движок — **Chromium-only** (ADR-036).

## Область

MV3-расширение для Chromium, дающее **две новые возможности** поверх уже готового pw-executor:

- **Record (запись вживую):** пользователь кликает/вводит → content-script захватывает события → grounding в шаги сценария (переиспользует `reconcile`/`ground_scenario`, M9.2b).
- **Co-pilot takeover/return (§F4):** агент ведёт прогон ↔ отдаёт управление человеку ↔ забирает — на ОДНОЙ живой сессии (поверх M9.6 CDP-attach).

**Это контракт-дизайн.** Код в этой волне НЕ пишется: нужны живой канал (M9.3 хвост, GAP-M9-03) + рекордер + транспорт + takeover-протокол, которых ещё нет. Реализация — отдельной волной после пререквизитов.

## Архитектура (MV3)

```
┌─────────── Браузер пользователя ───────────┐         ┌──────── Sentinel ─────────┐
│ content-script  (рекордер: click/input)     │         │                           │
│ service-worker  (MV3 background) ──WS/NM──▶  │◀───────▶│ control-API (M9.3, Go)    │
│ DevTools-panel  (старт/стоп · takeover)      │         │   + стриминг-эндпоинт      │
│ chrome.debugger (takeover = CDP)             │         │ brain (reconcile→steps)   │
└──────────────────────────────────────────────┘         └───────────────────────────┘
```

- **service-worker** — MV3 background: держит соединение с control-API, маршрутизирует события.
- **content-script** — рекордер: слушает `click`/`input`/`change`/`submit`, формирует `{selector-кандидаты, value (redacted), url}`.
- **DevTools-panel** (опц.) — UI: старт/стоп записи, кнопка takeover/return, статус.
- **chrome.debugger** — для takeover: attach к вкладке = CDP-контроль (та же модель, что M9.6 CDP-attach).

## Контракт (дизайн)

### 1. Транспорт extension↔brain (ADR-038)
- **Рекомендуется:** расширить **control-API (M9.3)** стриминг-эндпоинтом (**WS** `/v1/stream` или SSE) — переиспользует `127.0.0.1`-bind + bearer-token + CORS-allowlist (ADR-032). Расширение — WS-клиент с тем же токеном.
- **Альтернатива (air-gapped / без сетевого порта):** **native-messaging host** (stdio) — Chrome ↔ локальный бинарь по stdin/stdout; нет порта, но нужен per-OS host-манифест.
- Трекинг: **GAP-M9-14**.

### 2. Рекордер действий (ADR-038, GAP-M9-13)
- content-script → события → service-worker → транспорт → brain.
- **Redaction:** значения `input[type=password]` и secret-полей **НЕ записываются** (тот же принцип, что `PW_NO_TRACE` / `secretRef` в pw-executor).
- Минимальные `host_permissions` (`activeTab` / по запросу); запись **только при явном старте**.

### 3. Record→scenario (переиспользование M9.2b)
- Поток событий → `brain/scenario.py` `ground_scenario` / `reconcile` → шаги, **привязанные к реальным элементам** (как describe-mode, но на входе — записанные события вместо NL). Никаких сфабрикованных селекторов.
- Результат — `scenario.json` (тот же формат, что M9.2b), готовый к replay.

### 4. Co-pilot takeover/return (ADR-039, GAP-M9-15)
- **Состояния:** `agent-driving` ↔ `human-driving`. Сигнал takeover (кнопка в panel) → агент паузит, человек ведёт; return → агент снимает дельту состояния и продолжает.
- Реализуется **поверх M9.6 CDP-attach** (агент и расширение драйвят одну сессию через CDP).
- **Видимость:** Chrome показывает debugger-баннер при attach; auto-detach при return.
- Протокол: сигналы `takeover` / `return` / `state-sync` по тому же транспорту.

### 5. Threat-model
- Граница **❾** в `THREAT_MODEL.md` §4.9: чтение всех страниц, `chrome.debugger`=полный CDP, транспорт. Меры: минимальные permissions, debugger только по takeover-сигналу, локальный токен-транспорт.

## Критерии приёмки (контракта — НЕ реализации)
- [x] Архитектура MV3 + рекордер + транспорт + record→scenario + takeover описаны.
- [x] Транспорт-решение зафиксировано (control-API WS; native-messaging — альтернатива) — ADR-038.
- [x] Takeover/return-протокол зафиксирован — ADR-039.
- [x] Граница ❾ заведена в THREAT_MODEL.
- [x] Пререквизиты явны (GAP-M9-03 / 13 / 14 / 15).

## Отложено (реализация — отдельная волна, после пререквизитов)
- Скелет расширения (`manifest.json` MV3 + service-worker + content-script + panel).
- Стриминг-эндпоинт в control-API (или native-messaging host).
- Интеграция запись→scenario + e2e на фикстуре.
- Takeover/return на живой сессии.

> **Анти-галлюцинации:** MV3 / `chrome.debugger` (= CDP) / native-messaging (stdio host) — стандартные механизмы Chrome-расширений; сверить с актуальной документацией Chrome перед реализацией.
