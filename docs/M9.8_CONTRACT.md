## Область

MV3-расширение для Chromium, дающее **две новые возможности** поверх уже готового pw-executor:

- **Record (запись вживую):** пользователь кликает/вводит → content-script захватывает события → grounding в шаги сценария (переиспользует `reconcile`/`ground_scenario`, M9.2b).
- **Co-pilot takeover/return (§F4):** агент ведёт прогон ↔ отдаёт управление человеку ↔ забирает — на ОДНОЙ живой сессии (поверх M9.6 CDP-attach).

**Это контракт-дизайн.** Код в этой волне НЕ пишется: нужны живой канал (M9.3 хвост, GAP-M9-03) + рекордер + транспорт + takeover-протокол, которых ещё нет. Реализация — отдельной волной после пререквизитов.

## Архитектура (MV3)

```
┌─────────── Браузер пользователя ───────────┐         ┌──────── Sentinel ─────────┐
│ content-script  (рекордер: click/input)     │         │                           │
│ service-worker  (MV3 background) ──WS/NM──▶  │◀───────▶│ control-API (M9.3, Go)    │
│ DevTools-panel  (старт/стоп · takeover)      │         │   + стриминг-эндпоинт      │
│ chrome.debugger (takeover = CDP)             │         │ brain (reconcile→steps)   │
└──────────────────────────────────────────────┘         └───────────────────────────┘
```

- **service-worker** — MV3 background: держит соединение с control-API, маршрутизирует события.
- **content-script** — рекордер: слушает `click`/`input`/`change`/`submit`, формирует `{selector-кандидаты, value (redacted), url}`.
- **DevTools-panel** (опц.) — UI: старт/стоп записи, кнопка takeover/return, статус.
- **chrome.debugger** — для takeover: attach к вкладке = CDP-контроль (та же модель, что M9.6 CDP-attach).

## Контракт (дизайн)

### 1. Транспорт extension↔brain (ADR-038 → реализован ADR-043)
- **РЕАЛИЗОВАНО (M9.8-prep, ADR-043):** control-API расширен **hand-rolled WebSocket** `GET /v1/stream` (client→server) — закрывает оставшуюся половину GAP-M9-14 (server→client SSE уже был, ADR-040). **Без новых зависимостей:** `net/http` `Hijacker` + ручной RFC6455 (handshake `Sec-WebSocket-Accept` = `base64(sha1(key+GUID))` + frame codec). Reuse `127.0.0.1`-bind + bearer + Origin-allowlist (ADR-032).
  - **Аутентификация:** браузерный `WebSocket`/MV3-SW не шлёт `Authorization` → токен в `Sec-WebSocket-Protocol` как `bearer.<token>` (constant-time). Клиент предлагает ДВА сабпротокола — `sentinel.recorder.v1` + `bearer.<token>` — сервер валидирует токен и эхает обратно **только** не-секретное имя `sentinel.recorder.v1` (токен НЕ светится в ответном заголовке). CSWSH-защита: Origin-allowlist, если задан (без него / без `Origin`-заголовка единственный гейт = bearer-токен — оправдано localhost-bind). Расширение хранит токен в `chrome.storage` (не в репо).
  - **Ingest:** каждый text-фрейм = одно recorder-событие (NDJSON) → `runs/record-<session>/events.ndjson` (0700/0600); сервер шлёт greeting-фрейм с `session`-id + ack на каждое событие; `ping`→`pong`; idle-timeout 5 мин; cap 10000 событий, 1 MiB/фрейм. Фрагментация НЕ собирается (одно событие = один FIN-фрейм; фрагмент → close 1003). Это **транспорт + ingest**; grounding записи→scenario — отдельная веха (MV3-impl).
- **Альтернатива (air-gapped / без сетевого порта):** **native-messaging host** (stdio) — Chrome ↔ локальный бинарь по stdin/stdout; нет порта, но нужен per-OS host-манифест. (НЕ реализован; альтернатива для air-gapped-развёртываний.)
- Трекинг: **GAP-M9-14 — client→server WS DONE.**

### 2. Рекордер действий (ADR-038, GAP-M9-13)
- content-script → события → service-worker → транспорт → brain.
- **Redaction:** значения `input[type=password]` и secret-полей **НЕ записываются** (тот же принцип, что `PW_NO_TRACE` / `secretRef` в pw-executor).
- Минимальные `host_permissions` (`activeTab` / по запросу); запись **только при явном старте**.
- **Схема строки записи (ADR-138).** До этой волны формат существовал только в исходниках (`extension/src/shared/protocol.ts` и докстринг `brain/record_bridge.py`), в `docs/` — ни разу. Поток `events.ndjson` — это `RecorderLine`, то есть ЛИБО действие, ЛИБО смена маршрута:
  - действие: `{type: "click"|"input"|"change"|"submit", url, selectorCandidates: [{strategy, locator}], value?, secretRef?, verb?, key?, seq}`
  - маршрут: `{type: "route", url, how: "push"|"replace"|"pop", seq}` — адрес сменился БЕЗ загрузки документа; ни элемента, ни верба у такой строки нет
  - `seq` штампуется единой воронкой рекордера и строго возрастает, поэтому «порядок файла = порядок наблюдения» — проверяемое утверждение, а не допущение; разрыв в нём делает видимой уже существующую тихую потерю события при закрытом сокете
  - ⚠ **Сервер форму НЕ валидирует**: `cmd/control-api/ws.go` пишет строку побайтово, поэтому контракт держится ПОТРЕБИТЕЛЕМ (`brain/record_bridge.py`), а не гейтом на приёме
  - **Редакция адреса обязательна наравне с редакцией значений:** значение query-параметра с секретным именем заменяется на `REDACTED` в той же воронке `emit()`, для ВСЕХ строк. До ADR-138 `page_identity` срезал query, и секрет в адресе не доезжал до `scenario.json` — но в `events.ndjson` он попадал побайтово

### 3. Record→scenario (переиспользование M9.2b)
- Поток событий → `brain/scenario.py` `ground_scenario` / `reconcile` → шаги, **привязанные к реальным элементам** (как describe-mode, но на входе — записанные события вместо NL). Никаких сфабрикованных селекторов.
- Результат — `scenario.json` (тот же формат, что M9.2b), готовый к replay.

### 4. Co-pilot takeover/return (ADR-039, GAP-M9-15)
- **Состояния:** `agent-driving` ↔ `human-driving`. Сигнал takeover (кнопка в panel) → агент паузит, человек ведёт; return → агент снимает дельту состояния и продолжает.
- Реализуется **поверх M9.6 CDP-attach** (агент и расширение драйвят одну сессию через CDP).
- **Видимость:** Chrome показывает debugger-баннер при attach; auto-detach при return.
- Протокол: сигналы `takeover` / `return` / `state-sync` по тому же транспорту.

#### 4a. Brain-side R3 — транспорт takeover-сигнала до in-flight brain (развилка, 2026-06-30)
Брейн крутится как **per-run subprocess**; takeover приходит **асинхронно** из UI → нужно доставить сигнал так, чтобы брейн сделал LangGraph `interrupt`+persist (поверх R2a-checkpointer) и `resume` на return. Рассмотрены 3 варианта:
- **(A) Оркестратор RunControl gRPC (M8) — ✅ ВЫБРАН (юзер, 2026-06-30).** Расширить СУЩЕСТВУЮЩИЙ канал brain↔orchestrator (`cmd/orchestrator`, RunControl — уже делает token-reconcile + abort + SIGTERM): `Control += takeover` (brain-facing, как `abort`; брейн УЖЕ читает `Control` в ответе на каждый `ReportEvent`) + внешние RPC `Takeover`/`Return` (как `Abort`). control-API/WS форвардит сигнал → orchestrator (ставит takeover для `run_id`) → брейн узнаёт на следующем `ReportEvent` → `interrupt`. **Плюсы:** purpose-built канал, push-семантика, брейн уже опрашивает `Control` по-шагово (нулевой новый поллинг-цикл). **Минусы:** трогает `proto/runcontrol.proto` + orchestrator + brain + control-API; нужен запущенный orchestrator (`ORCH_ADDR`).
- **(B) Polled-флаг через shared store** — control-API пишет takeover-флаг в shared store, брейн опрашивает на superstep-границе. Плюс: нет proto/orchestrator-правок, переиспользует R2a-checkpointer. Минус: новый поллинг-цикл, латентность = интервал. **Отклонён:** RunControl уже даёт per-step pull бесплатно (B завёл бы параллельный канал).
- **(C) Новый control-API→brain дуплекс (WS/socket)** — брейн держит живое соединение к control-API. Минус: новый канал + брейн получает сетевого клиента. **Отклонён:** дублирует роль orchestrator-канала.
- **Risk-spike (2026-06-30, ✅ PASS):** LangGraph `interrupt()` mid-graph + `Command(resume=)` через `SqliteSaver` — паузит, persist'ит частичный стейт, резюмит с ТОГО ЖЕ места, **в т.ч. через свежий процесс** (takeover-окно может пережить брейн-процесс). Фундамент = R2a checkpointer.
- **Парность:** brain-side (interrupt/resume + RunControl `takeover`/`return` + WS-форвард) = моя **R3**, тест fake-клиентом; extension/CDP/panel = @0xCoDSnet **#47**. As-built → **ADR-054** при реализации.

#### 4b. Brain-side R3 — РЕАЛИЗОВАНО (ADR-054, 2026-06-30)

Вариант (A) реализован **аддитивно** (build не сломан; поведение без оркестратора байт-идентично — `poll()`→`continue` ⇒ узлы no-op, `plan_hash` не меняется):

- **proto (`proto/runcontrol.proto`):** `Control += bool takeover = 3` (отдельно от `abort`; **abort > takeover** — hard stop важнее паузы) + внешние RPC `Takeover(run_id, reason)` / `Return(run_id)` (по образцу `Abort`). Стабы Go+Python регенерированы тем же тулчейном (libprotoc 33.5 / protoc-gen-go v1.36.11 / -go-grpc 1.6.2 → diff аддитивный, без reformat).
- **orchestrator (`cmd/orchestrator`):** per-run флаг `takeover`; `ReportEvent` отвечает `Control{takeover:true}` пока pending (abort имеет приоритет в той же проверке); RPC `Takeover`/`Return` ставят/снимают флаг под `mu`. Watchdog (SIGTERM по budget-breach) НЕ трогается — пауза ≠ breach, токены во время паузы не копятся.
- **brain RunControl-клиент (`brain/runcontrol.py`):** `report()`/`poll()` возвращают **верб** `continue|abort|takeover` (раньше bool). `poll()` = 0-токенный heartbeat (`ReportEvent` с 0 токенов → бюджет +0), surface'ит pending takeover без траты бюджета.
- **brain-граф (`brain/graph.py`):** на superstep-границе узел `checkpoint` опрашивает оркестратор (`poll`); takeover → **арм** (state-латч `_takeover_armed`). Выделенный узел `takeover` делает **БЕЗУСЛОВНЫЙ** `interrupt()` (LangGraph персистит частичный стейт, `app.invoke` возвращает `__interrupt__`; человек ведёт живой браузер по CDP). Решение латчится в STATE в предыдущем superstep'е → на resume узел `interrupt()` доходит идентично (иначе volatile-poll сорвал бы запись возврата). Return: оркестратор по `Return` снимает флаг → брейн `Command(resume=payload)` резюмит **ту же нить** с точки паузы → `takeover` → обратно в `checkpoint` (re-poll; обрабатывает не-распространившийся ещё Return). Паттерн — из risk-spike (§4a).
- **abort > takeover в окне паузы:** если оркестратор ABORT'ит (budget-breach / внешний Abort), пока прогон стоит на takeover, узел `checkpoint` на resume **конвергит** прогон (не гоняет ещё один browser-цикл perceive→act) — hard stop приоритетнее возврата. Применяется и в `_run_explore`, и в cold-turn `_run_chat`.
- **brain-драйвер (`brain/__main__.py`):** `_resume_through_takeovers` — если прогон встал (`__interrupt__`), ждёт Return (poll → continue) и резюмит `Command(resume)`, пока граф не завершится / не выйдет `SENTINEL_TAKEOVER_TIMEOUT` (по умолч. 1800с; `0` = ждать бесконечно). Оборачивает invoke в **обоих** browser-путях (`_run_explore` + cold-turn `_run_chat`), чтобы takeover не снёс браузер до Return. No-op на обычном пути и без оркестратора.
- **control-API/WS (`cmd/control-api/ws.go` + `main.go`):** ТОТ ЖЕ сокет `/v1/stream` принимает control-фреймы в **отдельном envelope** `{"type":"control","action":"takeover|return","run_id":"<id>"}` → форвард в оркестратор (`CONTROL_API_ORCH_ADDR`, gRPC `Takeover`/`Return`) → ack `control-ok`/`control-error`. Все прочие фреймы — recorder-события (events.ndjson, как раньше). Namespace `type:"control"` (а НЕ голые верба `takeover`/`return`) исключает коллизию с recorder DOM-событием, которое легитимно может иметь `type:"return"` (клавиша Enter) и было бы молча проглочено. `run_id` — format-guard (`validRunID`: charset + ≤64); неизвестный `action` / невалидный `run_id` → `control-error` без форварда; fail-closed без оркестратора; собственный per-session cap на control-фреймы. **Cross-run authorization** (привязка `run_id`↔сессия) — на M9-LIVE (THREAT_MODEL ❾).
- **Тесты (offline, fake-клиент):** `tests/test_r3_takeover_offline.py` (interrupt→resume · свежий SqliteSaver-процесс · verb-precedence · drive-loop · регрессия no-orch · abort-во-время-takeover · cold-chat-takeover — 7) · `cmd/orchestrator/main_test.go` (Takeover/Return/precedence/isolation) · `cmd/control-api/ws_test.go` (parse/forward/missing-run_id/recorder-verb-collision; fake-оркестратор на unix-сокете). Гейты: go build/vet/**race**/gofmt · pytest (13 файлов) · bilingual · gitleaks.
- **Гейтировано в M9-LIVE:** живой takeover (расширение + `chrome.debugger`/CDP + panel = @0xCoDSnet **#47**) + оркестратор-per-run сокет-discovery в control-API. Здесь — транспорт + механика + offline-доказательство; e2e на живой сессии — следующей волной.

### 6. Rich co-pilot фронт (AG-UI / CopilotKit, ADR-044)
- **РЕАЛИЗОВАН скелет (M9.8-prep):** `frontend/` — Next.js (App Router) + **CopilotKit** (`@copilotkit/react-core`/`react-ui`/`runtime`) + **AG-UI**; Copilot Runtime → Vercel AI SDK `createOpenAI({baseURL})` → шим `POST /v1/chat/completions` (ADR-041). Один чат-тёрн = один прогон Sentinel; bearer-токен держится server-side в Runtime (не уходит в браузер).
- **DEV-only:** первый npm-фронт в репо — **НЕ air-gapped, НЕ в CI**, нужен `npm install` (вне `docs/*` air-gapped-зоны). Вернакулярные `docs/index.html#chat` / `docs/chat/` остаются offline-фолбэком. Версии пакетов верифицированы 2026-06-28; CopilotKit runtime = **v2/evolving** → сверять exports перед install.
- **Позже (M9.8-impl):** богатые AG-UI-события (tool-calls, прогресс прогона, state) поверх WS `/v1/stream` (ADR-043), когда появятся рекордер + takeover/return — duplex-канал, на который фронт «графтится».
