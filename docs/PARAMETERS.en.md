# Sentinel parameters — every environment variable

> 🌐 [Русский](PARAMETERS.md) (primary) · **English**

The complete list of variables the product reads. It is **DERIVED**, not kept by hand: the table
below is assembled by `scripts/gen_parameters_doc.py` from two sources, neither of which is prose —
a walk over the environment's readers (`scripts/env_inventory.py`) and the schema served by
`GET /v1/config-schema`.

**Why this matters more than it looks.** The repository already carries four hand-written lists of
variables — in [`TESTING.md`](TESTING.en.md), [`LOCAL_MODELS.md`](LOCAL_MODELS.en.md),
[`WINDOWS_TESTING.md`](WINDOWS_TESTING.en.md) and [`DISTRIBUTION.md`](DISTRIBUTION.en.md) — and all
four went stale identically and in one direction: none of them knows the `chat` role, real since
ADR-108b. That is not carelessness but HOW a hand-kept list fails (`DEVELOPMENT.md` §0, principle 5):
an extra entry is visible — a row for a variable that no longer exists breaks a run — while a
**missing entry is not**, because absence has no representation to look at. A fifth hand-written list
would go stale the same way, and its staleness would be just as invisible.

Those four tables stay: they are **recipes** («how to turn on Ollama», «what to install on
Windows»), not registries. The registry is here.

## How to read the table

| Column | What it means |
|---|---|
| **Variable** | the name the code reads |
| **What it does** | one sentence from the schema; for the unpublished ones, the **reason** it is not a setting |
| **Default** | the value next to the reader; `—` means there is none |
| **How it is set** | deployment setting · service process environment · run field · not a setting |

Three kinds of entry, and telling them apart is mandatory:

- **deployment setting** — reaches a run through the environment; set from the hub's Settings view,
  the setup wizard, `agentctl config set` or a variable;
- **service process environment** — read by the service itself (control-api, the CDP relay, the
  browser container, the journal) rather than by a run; set through compose or systemd. A separate
  kind not by taste: an entry among the settings is a promise that the value reaches **a run**, and
  that promise has already been broken once;
- **not a setting** — deployment wiring, a secret, or something derived that the product sets itself.
  Every such entry carries a reason rather than a label.

```bash
.venv/bin/python scripts/gen_parameters_doc.py          # rewrite both halves and parameters.json
.venv/bin/python scripts/gen_parameters_doc.py --check  # only report whether they are fresh
```

Freshness is held by `tests/test_parameters_documented_offline.py`: it rebuilds the document and
demands a byte-for-byte match, so a stale table goes red instead of reading as correct.
